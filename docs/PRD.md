# PRD · 需求文档

## 一句话

每周一自动把 GitHub 本周最火的项目整理成可折叠简报，我在简报下写想法，AI 去验证并回我。

## 谁在用

Kairo（王如权）。个人使用，单用户，无多租户需求。

## 问题

想知道技术圈每周在火什么，但：

- 自己刷 GitHub trending 要花时间，且看完就忘
- 星标列表越堆越多，从不回看
- 看到一个项目有想法，但没有顺手的地方记；记了也没人去验证

结果：**信息看过了，但没有转化成自己的东西。**

## 目标

让「看到一个项目」到「验证一个想法」之间的摩擦降到接近零。

成功标准（可验证）：

1. 每周一能收到，不用自己去找
2. 扫一眼标题和概括，30 秒内能判断要不要深入
3. 想深入时有完整简报，不用去读 README
4. 有想法时能立刻写下，不用切工具
5. 想法会被真的验证，而不是石沉大海

## 不做什么（明确排除）

| 不做 | 原因 |
|---|---|
| 不做公开产品 / 不部署到公网 | 个人工具，本地跑就够 |
| 不做多用户、不做账号体系 | 单用户 |
| 不做已读/未读状态机 | 增加复杂度，收益低 |
| 不做移动 App | 网页响应式即可；手机推送后续用 IM 解决 |
| 不做项目评分/推荐算法 | 榜单本身就是筛选，不需要二次排序 |
| 不做「收藏」「稍后读」 | 想法输入框就是轻量收藏 |

## 功能清单

### 第一期（已完成 2026-11-23）

- [x] 抓本周新建 + star 最多的 10 个项目
- [x] 每个项目抓 README 摘要（2200 字符）
- [x] 生成简报：为什么火 / 做什么 / 对你的用处
- [x] 卡片式页面，标题+概括常显，简报折叠
- [x] 卡片下输入想法，提交即存
- [x] 实践反馈回显在同一张卡片
- [x] 每周一自动生成（DSH 定时任务）
- [x] 每天 4 次自动处理未响应想法（DSH 定时任务）

### 第二期（待做）

- [ ] 跨周去重（同一项目连续上榜不重复推）
- [ ] `forYou` 从记忆自动生成（读 Kairo 最近在做什么）
- [ ] 实践员真正 clone + 实跑代码

## 验收方式

每期生成后，Kairo 打开页面：

- 能看懂 10 个项目分别做什么 → 通过
- 想展开时有实质内容，不是复述 README → 通过
- 提交想法后，下次打开能看到反馈 → 通过
