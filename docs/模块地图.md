# 模块地图（改一块会影响哪儿）

> **动手前必读。** 这里标出每个模块的职责边界和影响面。

## 数据流

```
GitHub API
    │
    ▼
[build-weekly.mjs] ──写──> data/weekly-<日期>.json ──┐
                                                     │
[人/模型 写简报] ────────> data/briefings-<日期>.json ─┤
                                                     ├──读──> [server.mjs: loadIssue()] ──> 页面 HTML
[浏览器 POST /idea] ─────> inbox/ideas.jsonl ─────────┤
                                                     │
[实践员] ─────────────────> inbox/reports.jsonl ──────┘
```

## 模块清单

### `tools/build-weekly.mjs` — 抓数据

**输入**：无（自己算一周前的日期）
**输出**：`data/weekly-<今天>.json`

**做什么**：
1. 算 `since = 今天 - 7 天`
2. 调 Search API：`q=created:>=<since>&sort=stars&order=desc&per_page=10`
3. 对每个 repo 抓 README（`Accept: application/vnd.github.raw`），裁到 2200 字符

**改这里会影响**：
- ↳ `data/weekly-*.json` 的结构 → `server.mjs` 的 `loadIssue()` 依赖 `repos[]` 的字段（repo/url/desc/lang/stars/forks/topics/readme）
- ↳ 定时任务「生成周报」的输出

**常见改动**：
- 想多抓几个项目 → 改 `per_page`（注意 API 分页上限 100）
- 想换榜单口径 → 改 `q`（比如 `pushed:>=` + `stars:>500`，或按语言过滤）
- README 太短/太长 → 改 `.slice(0, 2200)`

---

### `tools/preview.mjs` — 看素材

**输入**：命令行参数 `日期`
**输出**：屏幕

**做什么**：读 `weekly-<日期>.json`，把每个 repo 的描述和前 18 行 README 打印出来，给写简报的人（或模型）当素材。

**改这里会影响**：只影响屏幕输出，无副作用。安全改。

---

### `server.mjs` — 阅读器服务（核心）

**输入**：HTTP 请求 + `data/` 和 `inbox/` 的文件
**输出**：HTML 页面 / JSON 响应

**内部结构**：

| 函数 | 职责 | 改动影响 |
|---|---|---|
| `loadIssue()` | 合并 weekly + briefings，补默认值 | **核心**。改字段映射会让页面缺内容 |
| `readIdeas()` | 读 `ideas.jsonl` | 改格式会让已提交想法消失 |
| `readReports()` | 读 `reports.jsonl`，按 `ideaAt` 建索引 | 改 key 名会让反馈关联不上 |
| `renderPage()` | 生成整个 HTML（含内联 CSS/JS） | 改样式/布局都在这 |
| `esc()` | HTML 转义 | 别删，删了有 XSS 风险 |

**三个路由**：

| 路由 | 改动影响 |
|---|---|
| `GET /` | 主页面 |
| `POST /idea` | 想法入库。**字段校验在这里**（repo/text 非空） |
| `GET /api/ideas` | 只读调试接口，改它不影响主流程 |

**改这里会影响**：
- ↳ 页面显示（全部）
- ↳ 想法提交能否成功
- ↳ 实践反馈能否显示

**危险改动**：
- 改 `loadIssue()` 的字段名 → 页面立刻空白
- 改 `POST /idea` 的写入格式 → 实践员读不懂
- 删 `esc()` → 想法内容里的 `<` `>` 会破坏页面

---

### `flags.mjs` — 功能开关（横切关注点）

**输入**：`config/flags.json`（按 mtime 热加载）、环境变量 `GHW_FLAG_*`
**输出**：`getFlags()` → `{flags, meta}`

**内部结构**：

| 部分 | 职责 | 改动影响 |
|---|---|---|
| `DEFAULTS` | 出厂默认值 | **改这里等于改基线行为**，会影响所有未在 json 里声明的 key |
| `DESCRIPTIONS` | 开关说明 | 只影响 `/api/flags` 输出 |
| `DEPENDS_ON` | 父子级联 | 加条目会让某个开关自动跟随另一个 |
| `readFlagFile()` | mtime 缓存 + 解析 | 改缓存策略会影响热加载灵敏度 |
| `getFlags()` | 三级覆盖 + 级联 + kill switch | **核心**，所有开关值都从这里出 |

**改这里会影响**：
- ↳ 整个页面渲染（每处开关判断都读它）
- ↳ `POST /idea` 是否可用
- ↳ `/api/flags` 输出

**危险改动**：
- 删掉 mtime 检查 → 热加载失效，必须重启
- 让解析异常抛出 → **整页 500**。容错是硬要求
- 改 `getFlags()` 返回结构 → `server.mjs` 里所有 `F['xxx']` 全部失效

---

### `config/flags.json` — 开关配置

**写入者**：人（改文件）
**读取者**：`flags.mjs`

**注意**：必须是**无 BOM 的 UTF-8**。PowerShell 的 `Out-File -Encoding UTF8` 会写 BOM，导致 `JSON.parse` 失败（虽然会被容错兜住，但改动不生效）。用 `[System.IO.File]::WriteAllText($p, $s, (New-Object System.Text.UTF8Encoding($false)))`。

---

### `test-flags.mjs` — 开关测试

**输入**：无
**输出**：控制台，退出码（0 全过 / 1 有失败）

**做什么**：在临时端口 11499 起独立实例，测 56 项：开/关两态、热加载、级联、正交性、容错、代码保留。

**注意**：会临时改写 `config/flags.json`，**结束时自动还原**。别让它和正在跑的服务共用端口。

---



**写入者**：`build-weekly.mjs`
**读取者**：`server.mjs`（取最新）、`preview.mjs`

**结构**：
```json
{
  "week": "2026-11-23",
  "since": "2026-11-16",
  "repos": [{ "repo", "url", "desc", "lang", "stars", "forks", "created", "topics", "readme" }]
}
```

**注意**：`server.mjs` 按文件名排序取**最新**，所以命名必须是 `YYYY-MM-DD` 格式（字典序 = 时间序）。

---

### `data/briefings-*.json` — 简报

**写入者**：人 / 模型（定时任务里）
**读取者**：`server.mjs` 的 `loadIssue()`

**结构**：
```json
{
  "week": "2026-11-23",
  "items": [{ "repo", "summary", "whyHot", "brief", "forYou", "tags", "relevance" }]
}
```

**关键**：`repo` 字段必须和 `weekly-*.json` 里的完全一致，否则关联不上（`loadIssue()` 用 repo 名做 key）。没匹配上的项目会退化显示 GitHub 原始 desc。

---

### `inbox/ideas.jsonl` — 想法

**写入者**：`POST /idea`
**读取者**：`server.mjs`、实践员（定时任务）

每行一个 JSON：`{repo, text, at, status}`

**注意**：`at` 是 ISO 时间戳，**它是和 reports 关联的唯一 key**。改格式会导致历史反馈全部失联。

---

### `inbox/reports.jsonl` — 实践反馈

**写入者**：实践员（定时任务）
**读取者**：`server.mjs` 的 `readReports()`

每行一个 JSON：`{ideaAt, repo, status, at, report}`

**关键**：`ideaAt` 必须**逐字符等于** ideas 里的 `at`。差一个字符就显示不出反馈。

---

### `experiments/` — 试验场

**写入者**：实践员
**读取者**：无（人肉查看）

每次验证一个想法就在这建一个目录。**可以随时清空**，不进版本控制（`.gitignore` 已排除）。

---

## 依赖关系速查

| 我想改… | 必须同时检查 |
|---|---|
| 周榜口径（几个项目、什么条件） | `build-weekly.mjs` 的 `q` 和 `per_page`；`server.mjs` 不用改 |
| 简报字段（加一个「技术难度」） | `briefings-*.json` 结构 + `loadIssue()` 映射 + `renderPage()` 的 `.body` 区块 |
| 页面样式 | 只改 `renderPage()` 的 `<style>`，安全 |
| 想法提交多存一个字段 | `POST /idea` + 实践员的读取逻辑 + 页面渲染 |
| 反馈的显示格式 | `readReports()` + `.report` 样式 |
| 换端口 | `server.mjs` 的 `PORT` 或 `--port=`；定时任务里的地址也要改 |
| 加推送（微信/邮箱） | 新增 `notifier.mjs`，在 `build-weekly.mjs` 之后调用。**不要塞进 server.mjs** |
| **加新功能开关** | `flags.mjs` 的 `DEFAULTS` + `DESCRIPTIONS`（可选 `DEPENDS_ON`）+ `config/flags.json` + `server.mjs` 的判断点 + **`test-flags.mjs` 补用例** |
| **改开关的默认值** | 只改 `flags.mjs` 的 `DEFAULTS`。若 `flags.json` 里已显式写了该 key，则以 json 为准 |

## 扩展点（有意的设计）

1. **内容生成与投递分离** — `data/` 里的 JSON 是干净的中间产物。想推微信/飞书/邮箱，读这些 JSON 即可，不用碰 server
2. **简报与原始数据分离** — `weekly` 自动抓，`briefings` 可人工可模型，互不干扰
3. **想法与反馈分离** — 两个 jsonl 靠 `at` 关联，实践员可以换任何实现
4. **零第三方依赖** — 整个项目只用 Node 内置模块
